Steps 1–3 Rollout

How to take the three /planpro plans from the SOP page to merged code without two Claude sessions fighting over the same files. Three worktrees, three waves, two places where you stop and ask the plan owner.

Why this shape: steps 1 and 3 share no files, and step 2's first phase only overlaps step 3 in report.ts, in regions Git merges cleanly. The one real conflict is step 1 vs step 2 — both change the Add company dialog in companies.tsx, and step 2's migration 0067 needs step 1's 0066 first — so step 2's later phases wait.

  1. Get ready (once)

    In your main nct-layout checkout
    git fetch origin
git switch feat/new-layout
git pull --ff-only

  2. Create three worktrees

    A worktree is a second (and third, and fourth) folder on its own branch, sharing one Git history. Each Claude session gets its own folder, so no session can overwrite another's edits.

    From the nct-layout folder
    git worktree add ../wt-step1 -b feat/step1-enquiry-channel feat/new-layout
git worktree add ../wt-step2 -b feat/step2-credit           feat/new-layout
git worktree add ../wt-step3 -b feat/step3-contact-nomination feat/new-layout
    Then, inside each of the three folders
    bun install
  3. Wave 1 · run these at the same time

    Start three Claude sessions

    Open three terminals. In each, cd into its worktree, start claude, and give it the matching instruction. Change C:/nct-plans/ if you saved the plans elsewhere.

    Terminal 1 — in wt-step3
    Read C:/nct-plans/step-03-plan.md and implement it end to end, all phases.
Follow its section 10 to prove it works before telling me it is done.
    Terminal 2 — in wt-step2
    Read C:/nct-plans/step-02-plan.md and implement PHASE 1 ONLY (the credit check).
Stop after Phase 1's acceptance criteria. Do not start Phase 2 or Phase 3.
    Terminal 3 — in wt-step1
    Read C:/nct-plans/step-01-plan.md and implement it end to end, all phases,
including the migration 0066 and the seed-inbox fixture in Task 2.5.
Follow its section 10 to prove it works before telling me it is done.

    If you have the /execute skill, /execute C:/nct-plans/step-03-plan.md works too. The plain instruction above works in any Claude Code.

  4. While they run

    • Browser checks one worktree at a time. Every worktree's app wants :3101 (web) and :3000 (API), and the seeds assume 3101. Stop one worktree's dev servers before another session starts its browser check, or it silently tests the wrong app.
    • All three share the dev database named in apps/server/.env. That is safe in Wave 1: only step 1 migrates, and 0066 just adds a nullable column. Run bun run db:migrate in wt-step1 only.
    • Restart the API after editing packages/api. A hot reload keeps serving the old code and still answers 200.
    • Never use git stash or git reset, in any session, for any reason. If something is tangled, stop and ask.

  5. Check each branch before its pull request

    Do this in the worktree, once its session says it is done. Tick per branch — the boxes remember your ticks in this browser.

    CheckStep 3Step 2 · P1Step 1

gh pr create --base feat/new-layout --fill
  6. Merge order matters

    Merge in this order

    Ask the plan owner to merge each pull request into feat/new-layout in this sequence. Before a branch is merged, bring it up to date with what merged ahead of it.

    Bring a branch up to date — run inside its worktree
    git fetch origin
git rebase origin/feat/new-layout
bun run check-types
git push --force-with-lease
    If the rebase stops on a conflict

    Resolve it by hand, git add the file, then git rebase --continue. If you are unsure which side is right, run git rebase --abort — that puts the branch back exactly as it was — and ask. Never reach for stash or reset.

  7. Wave 2 · only after step 1 is merged

    Run step 2, Phase 2

    This is the phase that touches the same Add company dialog as step 1. Rebasing first puts step 1's change underneath, so there is nothing to conflict on.

    In wt-step2
    git fetch origin
git rebase origin/feat/new-layout
bun install
    New Claude session in wt-step2
    Read C:/nct-plans/step-02-plan.md. Phase 1 is already merged.
Implement PHASE 2 ONLY (the duplicate-company refusal, the near-match list
and the Name collisions filter). Stop after Phase 2's acceptance criteria.

    Run step 5's checks again, open the pull request, and have it merged.

  8. Stop · owner only

    Ask for the production collision count

    Do not run anything against production yourself.

    Phase 3 adds a unique index on company names. It fails on deploy if production already holds two companies whose names differ only by case or spacing. The repo blocks production connections on purpose; the plan owner takes this reading.

    Send the plan owner this message:

    Message to the plan owner
    Step 2 Phases 1–2 are merged. Before Phase 3, can you run the
read-only production collision probe from the step 2 plan and tell me
the "collision groups" and "collided companies referenced" counts?
  9. Wave 3 · after the count

    Run step 2, Phase 3

    The owner reportsWhat you do
    0 collision groupsRebase wt-step2, then give the session the instruction below. Task 3.0 (the merge script) has nothing to do.
    More than 0Stop. The duplicates must be resolved first — renamed or deleted in the app, or merged by Task 3.0's script, which the plan owner reviews before it runs. Come back when the count is 0.
    New Claude session in wt-step2 — only when the count is 0
    Read C:/nct-plans/step-02-plan.md. Phases 1 and 2 are merged, and the
production collision count is confirmed 0, so Task 3.0 is a no-op.
Implement PHASE 3 ONLY: migration 0067 and the case-insensitive index.

    Check that 0067 sits after 0066 in the journal with no gap, run step 5's checks, and open the last pull request.

  10. Close the loop on the SOP page

    After each merge, open the step on the SOP page. In What to fix first, tick every defect the pull request fixed as Done, and paste the pull request link as a comment on it. The next person then sees what is closed, and the Prompt box drops ticked defects from its brief.

  11. Clean up

    Only once a branch is merged and git status in its worktree shows nothing left.

    From the nct-layout folder
    git worktree remove ../wt-step3
git worktree remove ../wt-step1
git worktree remove ../wt-step2
