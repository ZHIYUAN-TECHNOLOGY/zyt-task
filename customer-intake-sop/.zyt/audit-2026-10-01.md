### op-001 - confirm - pattern unenforced-approval - steps 8, 10, 11, 20

**'Post to cost ledger' books an unapproved won quotation's fees, while Convert to order is refused** (sev: money, ledger id `au-post-to-cost-ledger-books-an-unapproved-`)

What the code does: Convert to order (`quotations.convertToOrder`) checks the quotation flow's `convert_order` gate, which the seeded Quotation review flow ticks, so a quotation that has not passed review is refused. The menu item beside it, 'Post to cost ledger' (`costLines.importFromQuote`), makes the same state change. It sets the quotation to `converted` and writes its fee lines into the cost ledger as billable receivables and payables. It checks only that the status is won or converted, and never asks the `convert_order` gate or the quotation's audit status. The editor shows the item for any won quotation, but shows Convert only when `auditStatus` is approved. The seeded flow does not tick the `export` gate, so a draft that was never approved can be sent, recorded as Won and then posted to the ledger. From there it can be billed (the cost_line `create_bill` gate is not seeded either) and invoiced, and no reviewer ever sees the prices. The quotation then reads `converted`, as if it had gone through the approved path.

### op-002 - confirm - pattern fake-default - steps 6, 8, 11, 20

**Applying a foreign-currency tariff with no rate on file silently prices it at exchange rate 1** (sev: money, ledger id `au-applying-a-foreign-currency-tariff-with-`)

What the code does: when sales apply a rate card (`quotations.applyTemplate`), each line's exchange rate is looked up in the org rate table. If no rate covers the currency, the lookup's `rateMissing` flag is thrown away. `computeFeeLineAmounts` then fills in a rate of `"1"`, so a USD 500 line is stored with a local amount of 500 as if it were ringgit. Quotation create and update run the same lookup but pass `rateMissing` to `assertUnratedFeeAllowed`. That call either refuses the line (when the org's 'fees can be saved without a rate' switch is off) or returns a warning that the page shows as a banner. `applyTemplate` does neither and returns only `{ feeLines }`, so the switch is bypassed and nobody is told. At step 8 the reviewer approves a total that adds foreign and local amounts at face value. At conversion the bridge copies the stored `"1"` onto the cost lines. The job's local-currency profit, its bills and its base-currency totals all inherit the wrong rate, and nothing on the line marks it as unrated.
