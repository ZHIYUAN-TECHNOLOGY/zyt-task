### op-001 - confirm - unreachable-screen - step 10 (sev: blocked)
**Decide (Won/Lost) cannot be recorded on a quotation that was not sent through the in-app mailbox.**

What the code does: the editor header shows Decide only when `status === "sent"` and `sentAt` is set, and the server's decide procedure refuses any quotation whose `sentAt` is null. Only the mailbox Send path (step 9) writes `sentAt`. A quotation handed over by PDF (Preview PDF / Export sheet from personal email), WhatsApp or at the counter, or sent while the mailbox is unavailable, can never have step 10 done: no decision date and no customer PO/reference is recorded. Convert to order still works because the convert guard refuses only `lost`, so orders exist with no recorded Won and the win-rate report misses those deals. The convert-guard docblock admits the gap and defers it to a manual "record as sent" action that does not exist.

### op-002 - needs-human - fake-default - step 19 (sev: money)
**72h demurrage countdown starts from when the poller saw the ship, not when it actually berthed, if the berth time cell does not parse.**

What the code does: the SBCP berth parser accepts only `DD/MM/YYYY hh:mm AM/PM` (two-digit day and month, AM/PM marker). A blank cell, single-digit day/month or 24-hour time returns `berthedAt` null, and the transition silently falls back to `observation.observedAt` (when the hourly or late poll noticed the vessel). That value is stored as `vesselBerthedAt` and `countdownDeadline` is set 72h after it. After a paused or failed poll the deadline can be hours or days later than the true one, so staff think they have more free time than they do and the forwarder pays demurrage.

Evidence:
- `packages/port-tracking/src/transitions.ts:157` - "const berthedAt = observation.berthedAt ?? observation.observedAt;"
- `packages/port-tracking/src/transitions.ts:171` - "countdownDeadline: new Date(berthedAt.getTime() + GATE_OUT_WINDOW_MS),"
- `packages/port-tracking/src/sbcp/berth-parser.ts:107` - "return { berthed: true, berthedAt: parseMytBerthTime(cells[berthTable.dateCol] ?? "") };"
- `packages/port-tracking/src/sbcp/berth-parser.ts:20` - "const BERTH_DATETIME = /(\d{2})\/(\d{2})\/(\d{4})\s+(\d{1,2}):(\d{2})\s*(AM|PM)/i;"

Refuter: PLAUSIBLE. The code path is real and live (sbcp/adapter.ts passes `berthedAt` only when truthy; nothing logs or flags the fallback; the parser's own header says a wrong berth time is permanent because the countdown is set once). Not in the ledger. Unproven that the SBCP dashboard ever renders a non-matching berth cell, so the trigger is likely but not demonstrated. Never applied by audit-apply; see Needs human.

### op-003 - confirm - fake-default - step 11 (sev: data)
**Converting a quotation with no Shipping Type creates an FCL order.**

What the code does: Convert to order copies the quotation's `shippingType` into the order's consign type and falls back to `"fcl"` when it is empty. Shipping Type is set by the four package cards; for a "No package" quotation it can only be set under More details, which step 5 says to open only when needed. A custom LCL, bulk or air quotation therefore becomes an FCL order, looks complete at step 14, and ledger filters and documents keyed on consign type treat it as a full-container job.
